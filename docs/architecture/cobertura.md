# Requirement coverage

This sheet maps each functional requirement in section 7.1 of the project document, and each of the four wireframed screens in section 9, to the code that serves it and the evidence that it works. Paths are relative to `src/` unless they start with `tests/` or `docs/`. Screenshots are in `docs/architecture/capturas/`.

The `u9-recorrido-NN-*.png` screenshots come from the section 8.10 walkthrough, which runs end to end in a headless browser on a freshly reset and seeded database. A new user registers, runs the real detector, saves the diagnosis, reports a result with a pending profile, and a second new user proposes a solution. The reviewer then approves the report, the solution and the profile, and the ficha for Elden Ring goes from "Sin evidencia verificada" to "Funciona con ajustes".

**Gap** marks something the requirement or wireframe asks for that the app does not do. A gap listed in `PLAN.md` "Cuts" says so.

Gaps by requirement:

- **RF-03.** A reviewer can create a game but cannot edit one after creation. The requirement asks to register and consult, so this is not a gap against its text.
- **RF-04.** On Linux without `vulkaninfo`, and on Windows always, the Vulkan level is projected from the GPU's PCI id and labelled "Proyectado" (ARCHITECTURE Q1). It stays "desconocido" when the GPU is not in the table or the capture predates U10. The diagnosis page shows the manual `vulkaninfo` command.
- **RF-04. Gap.** On a hybrid laptop the bash detector reads the first DRM card, which can be the integrated GPU, so the card projects that one. The PowerShell detector picks the adapter with the most VRAM.
- **RF-04.** The Steam Deck is recognized from DMI by the Linux detector and chosen by hand in the manual form. Other handhelds (ROG Ally, Legion Go) are not recognized.
- **RF-05.** Only installed Steam games are read. Other launchers and owned games that are not installed do not appear in "Tu biblioteca de Steam".
- **RF-07. Gap.** Performance settings exist only as profile steps and launch parameters. Wireframe 9.4's FSR, 60 FPS cap and memory compression toggles are not built (Cuts: one-click apply, the 5-step wizard).
- **RF-07.** The progress checklist has no automated test. Its behavior lives in `ui/progress.ts` and was checked in a browser in U7.
- **RF-08.** Report mode reads Steam on Linux only. Games from Heroic, Lutris or another launcher, and the Windows detector, still report by hand. When Steam does not say the exact release of a Valve tool, the form asks for it instead of guessing.
- **RF-09.** The hardware rules distributions out instead of recommending one, because no rule could pick one honestly. `screenDistros` reads only the GPU family and the architecture, and its registry holds only sourced facts: Bazzite has no Kepler support, Ubuntu 24.04 and Mint 22 ship kernel 6.8, Ubuntu's HWE kernel is 7.0, Arch needs `nvidia-580xx-dkms` for branch 580 and Bazzite the `bazzite-nvidia` image. Where the registry says `desconocido`, the reason asks the user to check. "Sin objeciones" means no reason against it was found, and the order is display order, not a ranking.

## Hardening checks (U9)

These ran on the U9 branch against the dev server, with the scripts kept outside the repo.

- **Accessibility.** axe-core 4 (WCAG 2.0 and 2.1, A and AA) over 28 pages for guest, user and reviewer, at 1280px and 390px. Before U9 it found 9 serious nodes, all `scrollable-region-focusable`: the copy box on `/diagnostico` and the ficha's matrix on a phone. After U9 it finds no violation at any impact. Color contrast passes on every badge tone, including `/_muestras`. axe's undecided contrast nodes are icon glyphs marked `aria-hidden`.
- **Keyboard.** Tab reaches every interactive element on 13 pages, and each focused element shows the global `:focus-visible` ring.
- **Phone width.** At 390px no page scrolls sideways; the ficha's matrix scrolls inside its card (`u9-movil-ficha.png`, `u9-movil-reportar.png`, `u9-movil-solucion.png`). Before U9 the report and solution forms overflowed by 139px and 388px.
- **Language.** Every page has `lang="es"`. A scan of the rendered text and the `aria-label`, `placeholder`, `title` and `alt` attributes finds no English UI words. Its only hits are the title "The Witcher 3" and the detector flag `--open`.
- **Errors.** With the database unreachable, every page answers 500 with "Algo falló de nuestro lado", and neither the HTML nor its dehydrated data contains SQL or connection text (`u9-error-bd-caida.png`). The server log keeps the full cause.
- **Empty states.** On an empty database the catalog says "Todavía no hay juegos en el catálogo.", and a search with no match says "Ningún juego coincide con estos filtros." An empty review queue, an empty guide list and a game with no approved environment each say so in words.
